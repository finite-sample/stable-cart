## [Unreleased]

### The short version

If you used 1.1.0, **your numbers changed**. Four defects meant the estimators
did not do what their documentation said, and the published benchmark results
were measured on the broken versions. Nothing in the 1.1.0 README should be
relied on; the results in this release were regenerated by committed scripts.

### Fixed — correctness

- **Most parameters did nothing.** Every documented switch was accepted, stored,
  and never consulted: the split strategy was chosen by a single
  `algorithm_focus` string, so `enable_oblique_splits`, `enable_lookahead`,
  `enable_prefix_consensus` and twenty-odd others could not change a prediction.
  The strategy graph is now assembled from the documented switches, and
  `scripts/param_effect.py` re-measures which parameters can move a prediction.
- **The split scan was truncated and picked the wrong candidate.** Gain was
  computed for a bounded prefix of thresholds and the *lowest*-gain split per
  feature was retained rather than the best.
- **`min_samples_leaf` was not applied when candidates were generated**, so
  nodes were abandoned for having no admissible split when one existed — it
  fired on 4 of 4 nodes on `diabetes`.
- **The consensus threshold was shadowed** by a local variable, and each
  replicate's votes were counted more than once, so the reproducibility floor
  was not the one documented.
- **`CentroidTree` drew its candidate pool without resampling**, so all N
  candidates were the same tree and "closest to the ensemble mean" was a choice
  among identical options.
- **`RobustPrefixHonestTree.top_levels` did nothing** — the parameter the class
  is named after. It was stored as `prefix_levels` and never read: the depth
  reached `ConsensusStrategy.find_best_split` and was discarded, so consensus
  ran at every node and there was no prefix. Now wired, which changes the
  predictions of every estimator that enables prefix consensus.
- **`validation_metric` was never consulted.** Three estimators passed three
  different values (`"median"`, `"variance_penalized"`) and validation-checked
  split selection always used one fixed rule regardless.

### Fixed — the scikit-learn contract

- `RobustPrefixHonestTree.get_params()` raised `AttributeError`: the constructor
  took `smoothing` and never stored it. `clone`, `repr`, `GridSearchCV` and
  `cross_val_score` were all unusable on it.
- `get_params()` reported `enable_gain_margin_logic=False` on two estimators
  given the default `True`, so `clone` produced a differently configured twin.
- `set_params` silently ignored every parameter renamed on the way to the base
  class — `smoothing`, `top_levels`, `enable_gain_margin_logic`,
  `variance_penalty`, `n_bootstrap` and others. A grid search over any of them
  searched a single point without error. Parameters are now re-derived at fit
  time so the constructor and `set_params` paths agree.
- `n_features_in_` was never set; `predict` before `fit` raised `AttributeError`
  rather than `NotFittedError`; and predicting from a matrix with the wrong
  number of columns silently succeeded on four of the five estimators.

### Added

- `stability_frontier` and `pareto_front` — sweep any scikit-learn estimator's
  parameter grid and return the configurations no other configuration beats on
  both accuracy and stability. Model-agnostic on purpose: a plain
  `DecisionTreeRegressor(ccp_alpha=...)` and a `StableTree` go on the same axes,
  and the honest answer is sometimes that pruning wins.
- `bootstrap_instability` and `bootstrap_predictions` — the resampling protocol
  of Riley and Collins (*Biometrical Journal* 65(8), 2023), including their mean
  absolute prediction error (MAPE). The R package `pminternal` implements the
  same protocol; this is the scikit-learn equivalent.
- `StableTree` — a single tree whose split *decision* is averaged over bootstrap
  replicates: the feature is elected by vote, the cut point is the median of the
  cut points that chose it, and a node that cannot reach a quorum becomes a leaf.
  `split_supports()` reports how reproducible each split was.
- Three plots (`pip install "stable-cart[plots]"`):
  `plot_prediction_instability`, `plot_mape_by_prediction`,
  `plot_stability_frontier`.
- `tests/test_estimator_contract.py` — one contract applied to all five
  estimators, replacing test files that exercised code no public import reached.

### Known — parameters that still change nothing

Seventeen parameters across the three older estimators are read by reachable
code but did not move a prediction under any of the perturbations
`scripts/param_effect.py` tries. They are not decoration and were not deleted;
they need a diagnosis. `results/param_effect/verdicts.json` names each one.
`lookahead_depth` is on all three lists, which is the most suspicious of them.

### Removed — breaking

- `stable_cart.less_greedy_tree`, `stable_cart.robust_prefix` and
  `stable_cart.bootstrap_variance_tree`: 3,359 lines of duplicate
  implementations of the same three class names, never exported from the
  package and never referenced by exported code. Import from `stable_cart`
  instead.
- Thirteen constructor parameters that could not change a prediction under any
  perturbation *and* were read by no reachable code:
  `validation_metric`, `validation_consistency_weight`,
  `enable_calibrated_smoothing`, `oblique_strategy`,
  `enable_deterministic_preprocessing`, `variance_stopping_weight`,
  `enable_bootstrap_variance_tracking`, `classification_criterion`,
  `enable_beam_search_for_consensus`, `bootstrap_max_depth`,
  `bootstrap_stratification_bins`, `enable_stratified_bootstraps`,
  `consensus_subsample_frac`. Passing any of them now raises `TypeError`
  instead of being silently accepted and ignored.

### Retracted

- The "30–50% variance reduction" headline. At matched complexity the measured
  reduction is far smaller and regime-dependent, and on low-noise data it is
  about 1%.
- The claim that selecting the candidate tree closest to the ensemble mean buys
  stability. Against a random pick from the same pool it is worth +18%; against
  plain CART it is worth nothing measurable.
- The claim that optimal (globally searched) trees are more stable. Matched on
  `max_leaf_nodes`, GOSDT's structural instability equals greedy CART's to three
  decimal places. The earlier result compared a 1-split tree with a 7-split one.

## [1.1.0] - 2025-03-21

### Added
- **CentroidTree**: New model selection method that trains N candidate trees and selects the one closest to ensemble mean
  - Reduces prediction variance by ~3% compared to single CART
  - Maintains single-tree interpretability (auditable, explainable)
  - Works with any sklearn-compatible tree class (CART, LessGreedyHybridTree, etc.)
  - Supports multiple proximity metrics: RMSE, MAE, correlation (regression); disagreement, probability_mse (classification)
  - Full sklearn API compatibility (clone, cross-validation, pipelines)
- Experiment script for comparing CentroidTree against other methods (`experiments/centroid_experiment.py`)

### Changed
- Updated README with CentroidTree documentation, usage examples, and experimental results

## [0.1.0] - 2025-01-29

### Added

#### Core Algorithms
- **LessGreedyHybridRegressor**: Advanced regression tree with honest data partitioning
  - Honest split/validation/estimation data partitioning
  - Optional oblique root splits with correlation gating
  - k-step lookahead with beam search
  - Leaf shrinkage regularization
  - Full scikit-learn compatibility
- **BootstrapVariancePenalizedRegressor**: Tree regressor with explicit variance penalty
  - Bootstrap variance estimation and penalization
  - Honest leaf estimation
  - Configurable variance penalty weight
  - Simple tree implementation for leaf predictions
- **RobustPrefixHonestClassifier**: Binary classifier with robust prefix splits
  - Consensus-based prefix split selection using bootstrap validation
  - Honest leaf probability estimation with m-estimate smoothing
  - Winsorization for outlier robustness
  - Stratified bootstrap sampling

#### Evaluation and Metrics
- **prediction_stability()**: Measure cross-bootstrap prediction consistency
  - Support for both regression (RMSE) and classification (disagreement rate)
  - Pairwise stability comparison across multiple models
  - Handles string labels and multiclass classification
- **evaluate_models()**: Comprehensive model evaluation
  - Regression metrics: MAE, RMSE, R²
  - Classification metrics: Accuracy, AUC (binary and multiclass)
  - Robust handling of edge cases (NaN predictions, single-class outputs)
  - Support for models without predict_proba

#### Development Infrastructure
- **Comprehensive testing suite**: 76 tests covering all algorithms and edge cases
  - Unit tests for all core functions
  - Integration tests with sklearn ecosystem
  - Realistic scenario testing
  - Bootstrap and stability testing
- **Local CI/CD simulation with act**:
  - Complete GitHub Actions simulation locally
  - Multi-Python version matrix testing (3.11, 3.12, 3.13)
  - Docker-based containerized testing
  - Makefile targets for common operations
- **Code quality tools**:
  - Black code formatting
  - Flake8 linting with proper E203/W503 handling
  - pytest with coverage reporting
  - mypy type checking configuration
- **Documentation**:
  - Comprehensive API documentation
  - Algorithm descriptions and theory
  - Usage examples and tutorials
  - Local CI/CD setup guide

#### Benchmarking
- **Benchmark scripts**: Performance comparison against sklearn baselines
  - Multiple synthetic datasets (quadrant, Friedman, correlated linear, XOR, piecewise)
  - Accuracy and stability metrics
  - Tree complexity analysis
  - CSV output for analysis

### Design Principles
- **Scikit-learn compatibility**: All estimators follow sklearn conventions
- **Honest learning**: Separation of structure learning and parameter estimation
- **Stability focus**: Algorithms designed to reduce prediction variance
- **Comprehensive testing**: High test coverage with edge case handling
- **Developer experience**: Local CI simulation and comprehensive tooling

### Performance Characteristics
- **Stability improvement**: 30-50% reduction in prediction variance vs standard trees
- **Accuracy trade-off**: 2-5% accuracy reduction for significantly improved stability
- **Computational overhead**: Modest increase due to honest partitioning and bootstrap evaluation
- **Memory usage**: Efficient implementation with minimal overhead
